# Phase 6 screenshot comparison review

The Phase 1A [analysis](DESIGN_ANALYSIS.md), [manifest](SCREEN_MANIFEST.md) and [token register](DESIGN_TOKENS.md) remain the design evidence. UI-246 is the common shell baseline; UI-204 supports dashboard content, UI-181 listing/context, UI-006 application catalog and UI-037 forms. Other implemented screen families are mapped in the generated comparison manifest.

The review captures 21 implementation views at each reference's original raster dimensions. See [capture/difference index](phase6-comparisons/INDEX.md), [mapping manifest](phase6-comparisons/manifest.json) and [numeric metrics](phase6-comparisons/metrics.json). Original reference PNGs are unchanged. `e2e/administration.spec.ts` captures the implementation; `scripts/compare-phase6-references.ps1` produces absolute RGB differences amplified three times and 50/50 overlays, without resizing originals. Text, fixture data and differing feature compositions are included in the difference, so a global pixel score is not a meaningful pass/fail fidelity target.

## Reviewed dimensions and differences

| Area | Evidence and implementation | Intentional difference / unresolved scope |
| --- | --- | --- |
| Backgrounds/sidebar/header | Existing navy/pale lavender/near-white tokens derived from original rasters; UI-246 shell retained | Raster gradients/noise are normalized to flat fills. UI-037 dark header, UI-007 pale sidebar and other source header variants do not override the common shell. |
| Shell geometry | 274px expanded rail, established header and 16px workspace gutters | UI-006/049/063/152/181 have different rail/header/title geometry. Font/zoom metadata is absent; source-specific geometry is not asserted equivalent. |
| Typography/spacing | Existing Arial fallback, title/body/metadata hierarchy, 4/8/12/16/24 rhythm | Exact source font and weights cannot be identified. New dashboard support panels use three desktop columns; layouts remain normalized and provisional. |
| Actions | Upper-right contextual controls, grid toolbar actions right, trailing row actions, form Save bottom-right, wizard navigation at bottom | Mock preview control and explicit mock labels are additional. Unimplemented IAM actions are omitted rather than presented as successful backend operations. |
| KPI/cards | Existing KPI card reused, trend projected inside card; listing summaries added above grid | Listing counts distinguish full query totals from current-page counts. Domain-specific analytics and detailed business sections remain mock/simplified. |
| Forms | Existing controls, labels, focus/error states and two-column reflow; preselected dropdown rendering corrected | Metadata fields demonstrate templates; they are not full SMTP, provisioning-rule or employee schemas. UI-037 is a family reference for generic create/edit forms, not an exact screen match. |
| Grids | Existing pale header/rows, fine borders, compact badges, selected-row sample, exports and column controls | Normalized fields differ from employee/account/business columns. Numbered pagination/current-page purple state now replaces the earlier Previous/Next-only discrepancy. |
| Detail/approval | Context panel, read-only fields, tabs, reason-required confirmed decision | Source business details, account correlation, domain relationships/history, branded logos/avatars and administrative operations are not fabricated. |
| Icons/borders/shadows | Existing Lucide, cool lavender borders, small radii and faint shadows from token system | Exact icon artwork, logos, shadow blur and source raster rendering remain unrecovered. |
| Mobile/dark | Existing token mappings, internal grid scrolling, stacked panels and wrapped controls | No dedicated approved role-dashboard/mobile/dark references exist; these are tested implementation variants, not extracted exact layouts. |

Material corrections during review: compact dashboard support layout, trends inside KPI cards, listing summary row, numbered pagination, model-to-option dropdown synchronization, neutral inactive detail badges, a selectable master list, and longest-matching parent menu highlighting on detail routes. Functional tests separately exercise the examples. Regression snapshots track this implementation and detect future changes; they do not prove equivalence to the approved business screenshots. Existing form/action snapshots were refreshed after reviewing small text-rasterization differences caused by the catalog's added placement/scroll geometry; no tolerance was raised to hide failures.

The comparison scope covers implemented sample views, not recreation of every one of the 253 reference screens. Exact Employee/Manager/IAM/System role dashboards, the integrated developer catalog, generic create/edit metadata forms, loading/error states and many new interactions have no exact dedicated reference. Their use of a related screenshot family is explicitly a comparison aid, not approval of a new pixel-identical design. Full domain screen reconstruction remains in the [issue register](../KNOWN_LIMITATIONS.md).
