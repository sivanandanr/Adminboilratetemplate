# UI components audit — Step 0 only

Audited 2026-11-15 against `prompts/ui-components.md`, `prompts/ui-patterns.md` and `prompts/ui-patterns-addon-progress.md`. Paths below are relative to `frontend/`. No implementation is included or approved by this audit.

## Scope and evidence

Read root and frontend `AGENTS.md`, the three prompts, current source, existing specs, architecture and design-system documentation. The actual library is `src/app/shared/ui/`. The requested output directory is therefore `frontend/docs/`, alongside the prompts. Each of the 35 files currently in `ui/` is listed below, including tests, CSS and the barrel. `forms.ts`, `block-ui.ts`, `offline-banner.ts` and `tasks.ts` do not currently exist.

Angular 20 standalone/OnPush, zoneless configuration, strict TypeScript, Signals, typed Reactive Forms, RxJS, Tailwind v4, AG Grid Community, ExcelJS and Lucide Angular are already present. Existing tokens in `src/design/tokens.css` remain authoritative, including Arial/Helvetica, semantic colors, spacing, radius and shadow. References exist in `docs/prompts/ui-patterns-ref/` (current screen and all eight pattern images), with approved source screenshots in `docs/design/screenshots/`. The saving reference was visually inspected; this source audit does not establish runtime screenshot equivalence, accessibility conformance or responsive correctness.

API shorthand: **CVA** below means `SmartValueAccessor<T>` composition with `id`, `label`, `placeholder` where exposed, `hint`, `required`, `disabled`, `readonly`, `errors`, and Reactive Forms value/touched/disabled integration. Current validation shows when touched or dirty, not only after submission.

Guideline references: **M** = main prompt section; **A/B/C** = add-on parts; **Components** = component mapping prompt. “No API break” means retain current selectors, inputs, outputs, service methods and result types; explicitly required behavior changes are still identified.

## Compatibility and decisions to review before implementation

- Preserve `ToastService.show`, ProgressService and status success/error, dialog results `{confirmed, reason}`, current option names and all barrel exports. New prompt APIs should be adapters/aliases, not replacements.
- Explicit behavior changes: toast count/timing/resume, submit-first validation, no password prefill, progress geometry/state colors and required scroll/footer behavior. Password prefill is the identified consumer behavior incompatibility; do not silently discard legitimate user input during change detection.
- Actual shared tabs use an underline, not the prompt's assumed pills. Existing tokens specify 6px/10px radii and Arial, not illustrative reference estimates. Preserve actual styles; no redesign or new palette is proposed.
- Semantic layer tokens are missing. Native `showModal()` uses the browser top layer: numeric CSS z-index alone cannot put toasts over modal dialogs. Resolve host/top-layer coordination as one shared overlay policy and verify focus/announcements in the browser.
- Backend task reload/list/retry and real upload progress need provider contracts. Existing export endpoints cover start/status/cancel/download only. Do not claim refresh persistence, post-logout execution or real upload percentages from client simulation.
- Foreground blocking activity must not override authoritative server expiry. Background tasks/polling must not refresh user activity. Use only non-sensitive cross-tab event metadata.
- Preserve safe error mapping; a server-supplied message is displayable only through a validated user-facing contract, never raw stack/exception content.
